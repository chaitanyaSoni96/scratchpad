# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
make build      # host binaries into bin/ (go build ./cmd/...)
make test       # go vet ./... && go test ./...
go test ./internal/store -run TestName   # single test (tested packages: internal/store, internal/web)
make web        # podman-build; loopback-only at http://localhost:8737
make web LAN=1  # bind the unauthenticated site on all interfaces
make stop       # stop the container
make logs       # follow container logs
make install-skill  # CLI on PATH + skill into ~/.claude and ~/.pi (scripts/install.sh)
make install-cli    # just the bin/scratchpad symlink into ~/.local/bin
make install         # native loopback alt: systemd --user, no container/sudo/read-only $HOME
make install LAN=1   # native install bound on all interfaces
make drop-mcp       # clear MCP registrations left by older installs
```

The container is built with podman from `Containerfile` (a `scratch` image holding two static binaries). `make web` mounts `~/.scratchpad` at `/data` and `$HOME` read-only (so `watch` symlinks resolve but the web process can never modify watched sources). Container and native installs bind loopback by default. `LAN=1` binds `0.0.0.0`; the site has no authentication, so this exposes content plus delete and notes-write endpoints to reachable clients.

## Architecture

Two binaries in `cmd/` share one store and coordinate **only through the filesystem** — there is no IPC or database. `~/.scratchpad` (override: `SCRATCHPAD_ROOT`) is the sole source of truth: anything that writes a folder there publishes an artifact.

- `cmd/scratchpad` — CLI (publish/watch/unwatch/watches/list/delete/notes). The **only** agent interface: agents drive it through bash, taught by `skill/SKILL.md`. There is deliberately no MCP server (the old one duplicated the CLI and split the guardrails); don't reintroduce one without a reason the CLI can't cover. `notes` gives the agent only `resolve`/`reply`, never `create`/`edit`/`delete`/`reopen` — those are rejected with an explanation (`userOnlyVerbs`) rather than silently read as a `<path>`, the same create-only-for-agents asymmetry as publish/delete.
- `cmd/scratchpad-web` — the htmx site: folder pages, sandboxed iframe previews, viewer overlay, SSE-driven live refresh, delete endpoint.

Internal packages:

- `internal/store` — all domain rules. An **artifact** is any directory directly containing a `.html` file; its whole subtree is assets, every directory above it is project path (any depth). Names must match `^[a-zA-Z0-9][a-zA-Z0-9._-]{0,99}$`; `artifactDir`/`ValidateFilePath` reject traversal. Publish is **create-only**: `os.Mkdir` (not MkdirAll) atomically claims the name, so races and existing names both surface as EEXIST — deletion is the user's action in the web UI, never an agent's. `Watch` symlinks an external folder in (same atomic create via `os.Symlink`), with one deliberate relaxation: an EEXIST whose link already resolves to the same target is a no-op (`linksTo`), so agents can watch unconditionally — any other target, or a real directory, still fails; `Delete` unlinks watched entries without touching the source and refuses anything whose path crosses a symlink. `Unwatch` is the deliberate counterpart to `Watch` — it removes *only* a symlink (refusing real directories) and so also reaches watched project trees, which are not artifacts and therefore invisible to `Delete`; `WatchLinkFor` maps any path to the link governing it, which is how the web layer offers unwatch on cards that merely live inside a watched tree. Artifacts cannot nest, enforced at both ends: `Publish`/`Watch` refuse a project path whose own directory holds an `.html`, and at read time the shallowest directory with `.html` wins (`ResolvePath` stops there; `List`/`Watches` never descend past one), so nesting that arrives another way — a watched tree, a `cp -r` — is absorbed as assets rather than refused. `ModTime` is the newest mtime in the tree (not the directory's) because the UI keys preview iframes on it. `internal/store/annotations.go` sidecars review notes one JSON file per **document**, not per artifact — `.annotations/<doc-path>.json`, so `index.html` and `notes.md` in one artifact keep separate note sets — with `rev`-guarded atomic writes (temp+rename); `ResolveNote`/`ReplyNote` are the only CLI-reachable mutations (the verb asymmetry above). `Delete`/`Unwatch` remove a name's whole `.annotations/<path>` subtree, so a re-published name never inherits old notes. `report.go` renders the markdown report shared by the CLI and the HTTP read endpoint.
- `internal/watch` — fsnotify over the whole root, debounced 250ms with a 1s maximum latency into the `/events` fan-out `Hub`. Initial registration is synchronous; reconciliation repairs missing/stale watches and recovers event overflow. Other watcher/reconcile failures are fatal to the web process so its supervisor restarts it rather than leaving a stale server running. A single Create event must hook an entire populated subtree.
- `internal/web` — handlers plus view-model building (`buildCards` handles folder tiles, single-artifact-folder collapse, multi-page collections, loose-markdown docs). Templates and static assets (htmx, sse, idiomorph) are `go:embed`ded — no runtime file dependencies. `internal/web/markdown.go` renders any `.md` via goldmark as a styled page. `internal/web/gzip.go` wraps the whole mux: it decides at first write (when Content-Type is settled) and compresses text types only — `text/event-stream` must pass through or SSE stalls, the wrapper must keep `http.Flusher` or the SSE handler 500s, and Range requests are skipped because encoding renumbers the offsets. `internal/web/notes.go` serves the review-notes routes: `GET /notes/{path...}` (markdown report by default, `?format=json` for raw, `?status=open|all`) and `GET /p/{path...}/notes` as its convenience alias — resolved only after every real path at that URL fails, so content actually named `notes` shadows it; `PUT`/`DELETE /notes/{path...}` are the viewer's `rev`-guarded writes, same trust tier as the delete endpoint.

Card previews are eager on purpose (`list.tmpl` explains why `loading=lazy` deadlocks), so every tile runs its artifact on every folder-page visit. `maxPreviewBytes` (1 MiB, measured on the artifact's **entry document**, not its subtree) caps that: past it `card.Heavy` is set and the tile draws a placeholder instead of an iframe, so one oversized generated artifact can't slow the folder it sits in. Keep new card-construction sites going through `artifactCard`/`withPreview`/`pageCard` or they will silently skip the cap.

Security model worth preserving: card previews run in `sandbox="allow-scripts"` iframes **without** `allow-same-origin` so auto-running artifact JS can't reach mutation endpoints; the viewer overlay is a deliberate trust decision and grants same-origin so annotation injection works. Opened artifacts are trusted, automatic previews are opaque.

Visibility is one decision function, `store.Visible(dir, name, isDir)` (`internal/store/ignore.go`) — every scan, the watcher, and every listing helper in `internal/web` route through it, so nothing drifts out of sync. **Default is visible**, dot-folders included; the `defaultIgnores` const is a built-in ruleset written in `.scratchpadignore` syntax and parsed by the same code, so it behaves like a file one level above the root and any `!line` overrides it. Keep it short and justified — an entry belongs there only if it is ruinously expensive to walk/watch (`.git`, `node_modules`, `.venv`) or holds credentials (`.env`, `.env.*`, `.netrc`, `*.pem`, `.ssh/`); ordinary dot-folders (`.agents`, `.github`) are content. The one exception to all of that is the top-level `.annotations` directory: `Visible` refuses it via a hard-coded reserved-name check, not through `defaultIgnores`, because that ruleset is meant to be `!`-overridable and notes storage must not be. Real `.scratchpadignore` files (gitignore subset + `include <file>`) layer on top: deepest file wins, last matching line wins. Hidden means unreachable, not just unlisted: `ResolvePath`/`ResolveDoc`/`VisiblePath` refuse hidden paths, so a hidden folder 404s. Parsed files are cached with a 1s TTL revalidated by mtime+size (`resetIgnoreCache` in tests).

Name validation is split by intent: `validateName`/`artifactDir` (strict `^[a-zA-Z0-9]…`, plus `checkPortableName` in `internal/store/names.go` rejecting reserved Windows device basenames like `CON`/`NUL`/`COM1` — with any extension — and names ending in a trailing dot or space) guard what the store **creates** (publish, watch); `validateSegment`/`existingDir`/`visibleSegments` guard what it merely **looks up or removes** (URLs, delete, unwatch) — looser, because watched repos name their own folders, but still traversal-safe, and deliberately do NOT apply the portable-name rule, so an existing entry a watched repository already named `CON` or `nul.txt` stays reachable and deletable. Visibility checks stop at an artifact directory: files inside an artifact are assets and are served as published.

Path containment permits exactly one symlink boundary: the store-root watch link. Browsing/listing can cross it but never follows a nested symlink in the watched source; publish project ancestors, delete/unwatch parents, and `.annotations` components must be real directories. CLI `publish -dir` accepts regular files/directories only. Publish requires exactly one of `-dir`/`-html`, permits at most one stdin input, and all commands reject excess positional arguments with usage status 2.

Env vars: `SCRATCHPAD_ROOT` (store root; the container sets `/data`), `SCRATCHPAD_URL` (advertised base URL, default `http://localhost:8737`). Ignore rules are files, not env: see `.scratchpadignore` above.

`skill/SKILL.md` (Agent Skills format) restates the store's rules for agents and is the single agent-facing contract — if publish/name/create-only semantics, the notes verbs, or CLI flags change, update the skill and `README.md` together, and re-run `make install-skill` to push the copies in `~/.claude/skills` and `~/.pi/agent/skills` (they are copies, not symlinks — an edit in the repo does nothing until you re-run it).
